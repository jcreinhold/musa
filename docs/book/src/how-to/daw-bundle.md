# Import a Musa bundle into Logic Pro or GarageBand

A *bundle* is one folder holding every open file a workstation can read — both MIDI documents, the notation, the
rendered mix, and one aligned audio stem per part and return — beside a manifest that says exactly what each file is and
what the formats could not carry.

```bash
musa render first.musa --to daw --profile logic -o "first for a workstation"
musa render first.musa --to daw --profile garageband -o "first for a workstation"
```

In the desktop app it is **File ▸ Export ▸ Export for a workstation**. Choose the workstation, then the folder. The
sheet that follows lists every file the bundle holds and everything the target formats cannot carry.

The folder must not already exist — the CLI refuses to overwrite one, so a bundle is never half-replaced. Pass
`--replace` when you mean to write over the last one.

## What is in it

| File | What it is |
| --- | --- |
| `score.mid` | The written reading: notated durations, one velocity |
| `performance.mid` | The played reading: the performance Musa realized |
| `score.musicxml` | The editable notation — Logic profile only |
| `audio/mix.wav` | The rendered master |
| `audio/parts/*.wav` | One stem per part output |
| `audio/returns/*.wav` | One stem per named bus |
| `musa-manifest.json` | What this bundle is, what produced it, and what it lost |
| `musa-origins.json` | Which exported note came from which source event |

Every audio file starts at project frame zero and is exactly as long as the mix, so they line up in a workstation with
no offset. **The stems do not sum to the mix**: a send duplicates signal, a return may share nonlinear processing, and
the master's limiting cannot be reconstructed from what reached it. The manifest's `routes` say where the signal
actually went.

## Logic Pro

Choose **one** route:

- `score.musicxml` if you want editable notation.
- `performance.mid` if you want the played reading for production.

Importing both makes two copies of one piece. If you want the notes without an interpretation, import `score.mid`
instead of `performance.mid`.

Drag `audio/mix.wav`, or the files in `audio/parts/` and `audio/returns/`, in beside it. They need no offset.

Musa cites Logic's import behaviour from the titles of Apple's guide rather than from measurement; Apple's page renders
only its table of contents to a fetcher. Where that matters, the manifest says so in the same words.

## GarageBand

GarageBand imports MIDI by dragging the file into the Tracks area, where Apple's guide says it "appears on one or more
software instrument tracks"; choose the instrument for each track in the Library. Import `performance.mid` **or**
`score.mid` — one of them, not both.

The audio files import the same way, and WAV is among GarageBand's documented audio formats.

GarageBand does not document MusicXML import, so the GarageBand bundle contains no notation file and says so in the
manifest rather than quietly omitting one. Export for Logic, or run `musa render --to musicxml`, if you want notation.

## What the bundle cannot carry

The manifest's `losses` are machine-readable and the export prints them. Every bundle reports at least two:

- **tuning** — neither a Standard MIDI File nor a WAV states a tuning, so a workstation plays the MIDI at whatever its
  own instruments are tuned to.
- **controller** — the MIDI files carry notes, tempo, meter, and key and no continuous controllers. The dynamics,
  articulation, and profile shaping of the piece are in the rendered audio, not in the MIDI.

Depending on the piece, it may also report **polytempo** (SMF has one tempo track), **polymeter** (SMF has one
time-signature track), **channel** (more parts than MIDI has channels, so two share one), and **notation** (whatever the
MusicXML exporter could not say, or the absence of a notation file in the GarageBand profile).

## What this is not

The bundle is a one-way reading. Musa does not write `.logicx` or `.band`, does not read a workstation's session
document, and there is no round trip — the `.musa` source stays the master record. `musa-origins.json` points exported
notes back at source events for a report to use; it is regenerated by the next export and nothing in it should be
edited.

A repeated export of the same piece writes the same bytes. Nothing in a bundle records when or where it was made.
