# 82. Quantities precede the studio vocabulary

**Status: governs nothing.** This record repairs the internal order and ownership boundaries of prompts 175–178 after
note 79 moved the sound language into ordinary source.

## The preparation defect

The first note-79 repair still asked prompt 175 to publish processor defaults, ranges, and units before prompt 176
declared the exact source quantity those facts inhabit. It also asked prompt 175's discoverability work to construct
registered machine values even though prompt 178 owns the executable primitive wrappers and private instrument machine
bodies. Executing that order would either invent a temporary Rust quantity schema again or implement prompt 178 early.

The source dependency is the simpler one:

1. prompt 176 declares the exact quantity and unit vocabulary and proves the single preparation conversion boundary;
2. prompt 175 declares processor contracts, defaults, ranges, documentation, and routing names using those source
   quantities, then makes the declarations discoverable;
3. prompt 177 declares indexed controls and performance values over the same quantity vocabulary; and
4. prompt 178 supplies executable source wrappers over registered primitives and uses them in private instrument machine
   bodies.

Filename order is not semantic order. The prompt graph carries the dependency by making 175 depend on 176.

## Ownership during migration

Prompt 176 introduces no new independently constructible Rust language model. Its opaque DSP projection is decoded from
a checked, zonked source artifact and performs no inference, coercion, default selection, or validation. The existing
public `WrittenQuantity` and `Unit` types may remain only where the not-yet-cut-over production path still calls them.
They gain no new caller or compatibility status, and prompt 180a deletes or privatizes them after complete differential
parity is proved.

Prompt 175 deletes the Rust catalogue as the authority for names, signatures, documentation, units, defaults, and
ranges. A remaining private registry entry may describe only a host-owned primitive contract: stable identity/version,
port and state formats, resource premises, preparation, and stepping. It cannot become a second presentation schema.
Executable wrappers that turn such registrations into source `Machine` values remain prompt 178's work.

This follows Peyton Jones chapters 3–6: source data and abstractions translate into a smaller implementation substrate;
they are not reproduced as target-language constructors merely for host convenience. It also follows Ousterhout chapters
7–8: quantity, catalogue, and machine layers must each hide distinct work rather than repeat the same public
abstraction.

## Unification and exactness discipline

Dimensions and control kinds are ordinary source indices. Omitted indices use only the existing Miller-pattern unifier:
metavariables applied to distinct local-variable spines, occurs and scope checks, postponed constraints, and refusal
when constraints remain unresolved. The source sound modules receive no unit-specific elaboration rule, coercion table,
host fallback, or decoder retry.

Decimal spelling is interpreted as an exact rational. Unit normalization is a total source function. Equality of
normalized values does not erase the lossless CST spelling used for diagnostics and structured edits. Conversion to
floating-point samples, coefficients, gains, or frame counts happens once in DSP preparation with explicit rounding,
range, and finite-result behavior.
