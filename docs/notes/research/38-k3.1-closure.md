# K₃.1 — closure of the stratified-kernel proof

**Status: fixed corrigendum and proof draft for independent review; governs nothing.** This note repairs exactly the
incompletenesses found in the frozen K₃ review [35](35-proof-review-k3.md). It does not replace or silently edit the
reviewed candidate [34](34-candidate-k3-stratified-kernels.md).

K₃.1 makes five corrections:

1. K₃ᴱ has exactly the already-governed source grammar—no general sum or `Result` claim;
2. contextual `Music` crosses to K₃ᵀ through an explicit accepted `instantiate_close` compiler judgment;
3. timeline equality uses complete canonical form; hashing is only a one-way filter;
4. open process graphs have typed boundary rows and drivers; and
5. lineage is a finite canonical **set** of traced edges, not a multiset.

No other K₃ theorem or recommendation is strengthened.

## 1. Exact elaboration stage

K₃ᴱ is exactly the grammar and semantics proved in `docs/rules/language/02-core-calculus.md`:

```text
A ::= b | unit | bool | nat | ratio
    | A×A | Option A | List A | A→A | Music
```

Terms are the governing monomorphic STLC forms, existing finite `Option`/`List` constructors and matches, governing
structural eliminators, saturated compiler-owned δ-operations, and controlled contextual-`Music` operations. The actual
multi-argument/product notation is inherited. There is no arbitrary `A+B` and no `Result A E` in K₃ᴱ. A domain operation
with expected absence returns `Option`; a malformed source or failed compiler judgment produces a located diagnostic
outside term evaluation.

Candidate T₂a's nominal data extension is not part of K₃ᴱ until its separate proof is accepted.

### Theorem E1.1 — governed totality

Every closed, well-typed K₃ᴱ term whose declaration graph and deterministic resource preflight are accepted evaluates to
exactly one finite value of its declared type, relative to the governing δ and `Music` ownership contracts.

*Proof.* The statement is precisely the governing calculus's deterministic-total-evaluation theorem with its §§4,
5.6–5.8 premises retained. No extra term or type constructor is quantified over. ∎

Resource acceptance is not a proof of mathematical normalization. It is an additional implementation condition which
rejects finite but impractically large accepted-by-the-type-system computations before publishing a partial value.

## 2. The exact K₃ᴱ→K₃ᵀ bridge

Ordinary evaluation has type family

```text

```

and is total on inputs satisfying E1.1. In particular,

```text

```

not `Term ScoreFact`.

The temporal bridge is a compiler acceptance judgment:

```text
Γ ⊢ m : Music
ρ ⊨ Γ
p : CheckedPlacement
budget_accepts(m,ρ,p)
──────────────────────────────────────────────────── Instantiate-Close
instantiate_close(m,ρ,p) ⇓ t : ClosedTerm ScoreFact
```

It consists of the governing contextual-instantiation operation followed by closure over the finite acyclic kernel-term
binding environment. A failure of typechecking, placement validation, resource preflight, or compiler invariant is a
diagnostic, not a K₃ᴱ value.

### Theorem B1 — bridge totality on accepted premises

If all premises of `Instantiate-Close` hold, there exists exactly one finite checked closed temporal term `t`, and K₃ᵀ
evaluation produces exactly the occurrence count and extent recorded by the accepted contextual fragment.

*Proof.* Existence, finiteness, closedness, and occurrence accounting are the governing contextual-instantiation and
closure theorem. Determinism follows because the source evaluator, placement, binding completion order, payload marks,
and closure traversal are deterministic under the fixed environment. K₃ᵀ T2 gives one normalized timeline from the
closed checked `t`. ∎

The corrected stage diagram is:


Other source values need not cross into K₃ᵀ.

## 3. Exact temporal equality and hash contract

For a closed temporal term `t`, write `can(t)` for the complete N1–N5 canonical timeline bytes after evaluation and
normalization. Define:

```text
t ≡_T u    iff    can(t) = can(u).
```

This comparison decides admitted semantic equality exactly because canonical payload bytes are the admitted payload
equality and canonical occurrence order retains extent and multiplicity.

The semantic hash is:

```text
h(t) = FNV1a128(can(t)).
```

### Theorem T2.1 — normalization and comparison

Every closed checked K₃ᵀ term has exactly one finite canonical form. Equality of complete canonical bytes decides `≡_T`.
Moreover,

```text
t ≡_T u  ⇒  h(t)=h(u),
```

but the converse is not a theorem.

*Proof.* Structural totality and uniqueness are governing T1–T4 and N1–N5. The equality equivalence is the definition of
N4 at canonical form. The hash implication follows by applying one deterministic byte function to equal byte strings. A
converse cannot hold for a fixed 128-bit codomain and infinitely many canonical timelines. ∎

A cache may use `h` to reject a miss cheaply. A hit confirms complete canonical arguments, as K₃ C1 already requires.

## 4. Open whole-tick process graphs

Fix a nominal tick `k`. A process graph has finite typed boundary rows:

```text
Graph k I O
```

where `I` and `O` have distinct labels. Let:

```text
SourcePort(G) = { In(i) | i∈I } ∪ { OutOf(p,o) | o∈O_p }
SinkPort(G)   = { Into(p,i) | i∈I_p } ∪ { Out(o) | o∈O }.
```

Each source and sink has one port value type at tick `k`. An edge is:

```text
wire(source,sink)
reg(register_id, initial, source, sink).
```

An edge is well typed when source and sink value types are equal. Every sink has exactly one incoming edge. A source may
drive several sinks; this is explicit graph fan-out over copyable per-tick port values, not a linear-process claim. Each
`reg` id is distinct and `initial` has the edge's value type.

Boundary-to-boundary wires/registers are allowed. A graph with no internal node can therefore implement identity,
permutation, or a registered boundary delay.

### 4.1 Validation

The instantaneous **node dependency graph** has an edge `p→q` iff an unregistered `wire(OutOf(p,o),Into(q,i))` exists.
Boundary sources have no predecessor node. Wires to boundary outputs add no node dependency. Registered edges add no
current-tick dependency.

`close : OpenGraph k I O → Option (Process k I O)` validates finite identity, port typing, unique drivers, and
acyclicity of this node graph. A compiler implementation returns diagnostics, but the calculus uses `Option`. It stores
a deterministic topological order, choosing the least stable node id among available nodes.

### 4.2 Tick transition

At tick `n`, inputs provide one value for every `In(i)`. Each register provides its stored old value to its sink. Then:

1. follow boundary-source wires to their sinks;
2. visit nodes in stored order; every node input now has one value, so call its whole-node `step_p` exactly once and
   route each output along instantaneous wires;
3. after all nodes, read each boundary `Out(o)` from its unique driver; and
4. atomically commit every node next state and each register's source value as its tick-`n+1` stored value.

For a registered source whose source is a node output, the value is available by the end of the node order. For a
boundary input it was available at step 1. Boundary outputs never source a register and cannot create a dependency back
into the graph.

### Theorem P1.1 — open-graph totality and determinism

If `close(G)=Some(P)`, then for every node/register initial state and every boundary input history, `P` produces exactly
one boundary output and next state at every finite tick.

*Proof.* Induct on ticks. At one tick, all boundary inputs and old register values are fixed. Induct on the stored node
order. Every node-input driver is one of:

- a boundary input, routed before the node order;
- an old register value, read before the order; or
- an instantaneous predecessor output, whose node precedes the current node by topological sorting.

Unique-driver validation gives exactly one input value. The primitive ownership contract gives exactly one whole-node
output and next state. After finitely many nodes, each boundary output has its one validated driver and every register
source value is known. Atomic commit produces one next state. The tick induction gives the unique history. ∎

### Theorem P2.1 — open-graph causality

If two boundary input histories agree through tick `n`, the output histories of an accepted graph agree through tick
`n`.

*Proof.* Simultaneous induction on ticks and, within a tick, on stored node order as in P1.1. Initial states are fixed;
old register states agree from the preceding tick induction; boundary values agree by hypothesis; deterministic node
steps preserve equality. ∎

### Corollary P3.1 — registered-cycle condition

Every directed cycle from node output through node inputs contains a registered edge.

*Proof.* A cycle using only instantaneous wires would induce a cycle in the accepted node dependency graph. ∎

The calculus does not accept the K₂ port-DAG counterexample because a whole node runs only after every input is driven.

## 5. Current audio implementation is not a fixed block tick

K₃.1 withdraws the shorthand “specify the current studio as `Block(r,b)`.” Current `RenderPlan::render` processes the
caller's remaining frame count in chunks no larger than configured `b`; the implicit feedback boundary can therefore
advance once for one 512-frame call or four times for four 128-frame calls. Its present semantics depends on the
caller's chunk partition.

Three honest implementation routes remain:

1. **Explicit fixed-tick register:** add K₃ᴾ register edges to the prepared IR and internally buffer partial host calls
   so semantic tick boundaries do not follow caller partition.
2. **Partition-keyed process:** expose the complete chunk partition in the execution semantics and canonical key. This
   is truthful but makes host call shape part of sound.
3. **Frame-causal SCC:** implement the finer executable per-output contract from [33](33-studio-feedback-semantics.md),
   making host chunks batching rather than semantics.

The long-term recommendation remains route 3. Route 1 is the smallest prototype of P1.1. Until one lands, documentation
should call current feedback deterministic for a fixed render-call partition, not block-partition independent.

## 6. Set-valued lineage

Every presentation has a finite anchor set with a distinguished root. A lineage `L:S→T` is a finite canonical **set** of
complete traced edges:

```text
Edge S T = (source:Anchor_S, target:Anchor_T, trace:List Step).
```

All anchors exist, every target has at least one incoming edge, and a generated step names a source root or rule/site
anchor. Set equality is equality after lexicographic canonical sorting and exact duplicate removal. There is no edge
multiplicity.

If two derivations with otherwise identical endpoints and steps must remain distinct, `Step` includes a stable
`DerivationId`; the resulting complete edges are then not duplicates. An implementation must not use accidental vector
position as that id.

Composition is:

```text
M∘L = {
  (s,u,trace_L ++ trace_M)
  | (s,t,trace_L)∈L and (t,u,trace_M)∈M
}.
```

The braces denote a set; duplicates are removed after construction.

### Theorem L1.1 — set lineages form a category

Composition is associative and the set of `(a,a,[])` edges is a two-sided identity.

*Proof.* Both associations contain an edge exactly when there are anchors `t,u` and constituent edges along the same
three-step path. Trace list concatenation is associative, so the complete produced edge is identical under either
grouping. Set comprehension and deduplication therefore yield equal sets. Identity contributes the same endpoint and
empty trace; concatenation with empty leaves the edge unchanged. ∎

### Theorem L2.1 — target coverage composes

If every target of `L:S→T` and every target of `M:T→U` has an incoming edge, every target of `M∘L` has an incoming edge.

*Proof.* For target `u`, choose `(t,u,q)∈M`, then choose `(s,t,p)∈L`. The composite set contains `(s,u,p++q)`. Exact
deduplication cannot remove the last copy of an existing set element. ∎
