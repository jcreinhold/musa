# K₃.3 — integration closure

**Status: final integration corrigendum for independent review; governs nothing.** The K₃.2 review
[42](42-proof-review-k3.2.md) accepted semantic framing and typed lineage paths, but found three missing integration
contracts and one abbreviated R1 which did not match its proof. This note adds exactly those premises. It does not alter
the accepted F1–F3, T2.2, L0, L0.1, L1.2, or L2.2 arguments.

## 1. Versioned semantic schemas

A payload admission supplies:

```text
PayloadSchema A = {
  owner_type_id    : StableTypeId,
  quotient_version : SchemaVersion,
  key              : A → ByteString
}.
```

`key` is total and deterministic and defines the equality admitted by the temporal kernel. Changing which stored fields
the key observes, or changing their canonical encodings, requires a new `quotient_version`. A schema id cannot be reused
for a different key contract.

The exact semantic encoding is now parameterized explicitly:

```text
encode_sem[TimelineEncodingVersion,PayloadSchema A](M).
```

Its domain-separated header contains both versions and `owner_type_id` before the framed extent and occurrences from
[40 §3](40-canonical-framing-bug.md). Thus equal bytes are interpreted only at one fixed temporal encoding and one fixed
payload equality. Cross-schema byte equality is not semantic equality.

### Lemma S1 — versioned framing remains complete

At fixed `TimelineEncodingVersion` and `PayloadSchema A`, framed byte equality is equivalent to equality of `Sem_A`.
Encodings under different schema headers are unequal.

*Proof.* The first statement is F2. The version and owner fields are canonically framed components preceding the old
structure. A differing component yields a differing uniquely decoded structure and hence differing bytes. ∎

Persisted cache keys contain the complete schema header, not merely the digest of the remainder.

## 2. Well-formed artifact registries

A presentation reference is:

```text
PresentationRef = (PresentationId,ArtifactVersion).
```

An immutable finite registry `ᶜ` maps each reference to one descriptor:

```text
PresentationDescriptor = {
  kind         : PresentationKind,
  anchor_table : finite map AnchorId ↦ AnchorDescriptor,
  root         : AnchorId,
  sites        : finite set AnchorId,
  schema       : PresentationSchema,
  manifest     : CanonicalBytes
}.

PassDescriptor = {
  id            : PassId,
  source_kind   : PresentationKind,
  target_kind   : PresentationKind,
  evidence_type : EvidenceSchema,
  region_type   : RegionSchema
}.
```

`RegistryWellFormed(ᶜ)` holds exactly when:

1. presentation references are unique map keys and resolve to one descriptor;
2. a `PresentationId` is permanently owned by one nominal presentation kind, while each changed artifact receives a
   distinct `ArtifactVersion`;
3. anchor ids are unique inside their presentation, and `root` and every `site` occur in its anchor table;
4. pass ids resolve uniquely to one descriptor;
5. every qualified anchor and pass referenced by an admitted hop resolves;
6. every hop's source and target presentation kinds equal its pass descriptor's kinds; and
7. the registry is immutable for checking and composition.

An implementation does not prove global uniqueness by trusting a finite digest. A stored artifact carries or resolves a
canonical manifest. When registries are merged, equal presentation references must have byte-identical manifests and
equal descriptors, and equal pass ids must have byte-identical pass descriptors; otherwise the merge is rejected as an
identity/version conflict. A digest may locate a manifest, but exact manifest comparison confirms it.

A qualified anchor is now `(PresentationRef,AnchorId)`. Every lineage theorem in K₃.2 has `RegistryWellFormed(ᶜ)` as an
explicit premise.

### Lemma G1 — qualification is functional

Under `RegistryWellFormed(ᶜ)`, every admitted qualified anchor has exactly one presentation descriptor, presentation
kind, and anchor descriptor; every admitted pass id has exactly one pass descriptor.

*Proof.* Finite-map lookup at a unique presentation reference or pass id returns at most one value. Conditions 3–5 give
existence for admitted references. Conditions 2 and 6 fix the associated kind. ∎

### Corollary G2 — the K₃.2 category is well typed

For a fixed well-formed registry, the K₃.2 path and lineage category theorem has functional object, endpoint, pass-kind,
root, and site judgments.

*Proof.* Apply G1 at every formation premise, then apply L0–L2.2 unchanged. ∎

For separately stored lineages, composition first validates a common merged registry. Inclusion into a larger
well-formed immutable registry preserves old path judgments because existing reference mappings cannot change.

## 3. Canonical lineage records

Every field used by stored lineage implements one versioned canonical-data contract:

```text
CanonicalData X = {
  schema : StableTypeId × SchemaVersion,
  encode : X → ByteString,
  compare : X × X → Ordering
}.
```

The contract requires:

1. total deterministic encoding and comparison;
2. `encode(x)=encode(y)` iff `compare(x,y)=Equal`;
3. `compare` is a total order on the admitted equality classes; and
4. every variable-size child encoding is length-framed.

`PresentationRef`, `AnchorId`, `PassId`, `DerivationId`, `PresentationKind`, `RegionMap`, `CanonicalEvidence`, every
role, and every schema reference satisfy this contract. Evidence and regions include their owner schema ids. A hop
encodes a fixed tag followed by its length-framed fields. A path encodes its vertex count and vertices, then its hop
count and hops. A lineage normalizes by lexicographic path order followed by exact duplicate removal.

### Lemma C2 — canonical lineage equality is decidable and exact

For finite well-formed paths, structural path equality is decidable and equivalent to equality of canonical path bytes.
For finite lineages, normalized-set equality is decidable, independent of insertion order, and retains two derivations
exactly when some canonical field (including `DerivationId` when supplied) differs.

*Proof.* Finite products and lists of decidable total orders have the lexicographic decidable total order. Unique
length-framing gives structural-byte equivalence by induction over the record/list grammar. Sorting a finite list by
that order terminates; removing adjacent equal values yields the unique finite-set representative. ∎

This is an equality for derivation artifacts. It is not temporal semantic equality and is not a claim that two different
evidence objects proving the same musical proposition must compare equal.

## 4. Exact execution factorization

Let `Sem_Gesture(M)` be the complete structured semantic form under the admitted, versioned gesture payload schema. The
execution operation is:

```text
prepare_execution :
  Sem_Gesture × Bindings × Seed × Options
  → Result PreparedExecution PrepareError.
```

`Options` includes every preparation choice which may affect acceptance or execution, including sample rate, channel
contract, block/tick policy, requested render bounds, and deterministic quality policy. Each non-scalar argument has its
own versioned admitted equality and complete canonical encoding.

Presentation data omitted by `Sem_Gesture` is available only to the separate operation:

```text
prepare_lineage :
  Presentation_Gesture × PreparedExecution
  → Lineage Gesture Plan × List RealizationLoss.
```

It cannot modify `PreparedExecution`.

### Theorem R1-K₃.3 — semantic execution factorization

If

```text
Sem_Gesture(M)=Sem_Gesture(N),
B=B',  s=s',  O=O',
```

then

```text
prepare_execution(Sem_Gesture(M),B,s,O)
  = prepare_execution(Sem_Gesture(N),B',s',O').
```

Equality is equality of the complete `Result`: both calls fail with the same canonical error or succeed with equal
execution specifications.

*Proof.* Both applications receive equal arguments in every position. `prepare_execution` is a pure deterministic
function of exactly those arguments, so substitution yields equal results. It cannot inspect presentation fields because
its input type contains only `Sem_Gesture`. ∎

### Corollary R1-frames — conditional frame equality

If the common result succeeds, fixed allocation semantics, equal external input histories, equal parameters/seeds and
initial node/register states, and deterministic conforming processor transitions produce equal output frames.

*Proof.* Equal `PreparedExecution` values allocate equal process definitions under the stated allocation premise. Apply
the accepted K₃ᴾ totality/determinism theorem tick by tick. Cross-platform floating-point or device equality is not
derived unless processor conformance promises it. ∎

`prepare_lineage(Presentation_Gesture(M),execution)` and `prepare_lineage(Presentation_Gesture(N),execution)` may
differ. R1 states no lineage equality.

## 5. Exact cache theorem

For one versioned operation, define complete execution arguments:

```text
ExecArgs = {
  operation_version,
  timeline_encoding_version,
  gesture_payload_schema,
  Sem_Gesture,
  bindings_schema, Bindings,
  Seed,
  options_schema, Options
}.
```

`ExecArgs` itself has one named `CanonicalData ExecArgs` record. It length-frames every displayed field, including the
complete canonical `Seed`, and its schema version changes if the field set, field order, or any admitted equality
changes. Thus “exact framed-argument equality” below is one defined comparison, not an informal conjunction assembled by
a cache caller.

A cache stores `(hash(encode(ExecArgs)), encode(ExecArgs), Result)`. It inserts only the result returned by the named
operation version on those exact arguments. Lookup uses the digest to find candidates and returns a candidate only after
exact framed-argument equality.

### Theorem C1.3 — collision-checked cache correctness

A returned cache hit equals recomputation of `prepare_execution` on the requested arguments.

*Proof.* Exact framed equality and the canonical-data contract give equality of every complete argument and select the
same operation version. The insertion invariant identifies the stored result with that function on the stored arguments.
Substitution yields the requested recomputation. Hash collisions can add candidates but cannot pass exact confirmation.
∎

## 6. Closure claim

K₃.3's complete candidate now consists of:

- the exact existing K₃ᴱ grammar and its separately accepted `instantiate_close` bridge;
- the existing unequal-extent finite temporal algebra;
- versioned structured temporal equality and an injectively framed storage encoding;
- a whole-node registered process IR with explicit boundary rows and fixed-state causality;
- typed path lineage over a well-formed immutable artifact registry;
- canonical finite lineage records; and
- preparation factored through semantic execution arguments, with presentation-only lineage.

The candidate still does **not** claim that these proposed representations exist in current Rust. The immediate
implementation obligation after acceptance is the governing N3–N6 framing bug, because current hashing is already known
wrong. Lineage and process prototypes come later. Candidate T₂a remains a separate source-language theorem and is not
made correct by this closure.
